# 蓝色横屏参考风格

本页用于蓝色横屏设计、制作与视觉QA。具体数值读本地profile，字段读 [episode-format.md](episode-format.md)。设计原则总结了本地制作与外部视频参考的观察；原录屏、联系表与声音素材没有确认再分发权，不包含在本仓库。可见成片不能证明他人的后台采编、真实音源或核验流程。

## 固定识别与内容弹性

1920×1080 横屏，近白浅底、白色卡片、深色正文、蓝色大标题与当前栏目。辅助色由 profile 统一，帮助区分卡位；颜色不是可信度或风险等级。保持轻边线、轻阴影、线性图标与留白；不要改成深色科幻屏、霓虹 HUD、持续占位的数字人或大量装饰 B-roll。外来品牌海报保留其原色，统一感来自共同资料窗口，不靠把所有素材染蓝。

常见节目时长与条数仅作观察，按真实候选、理解负担和实测声音适配，不强制配额。

## 新闻卡片

建立概览和 1–6 卡新闻页：单卡居中、两卡/三卡单排、四卡2×2、五卡上三下二且第二排居中、六卡3×2。每张讲一个具体方面，不足就少卡。素材海报里的模块、软件窗口里的面板不计作栏目卡数。

排版先定列宽，用真实字体测正文换行；每排取本排最高卡，同行齐高，两排不必同高。标题、间距与卡组作为整体，在导航和字幕安全区间内平衡位置。正文多时卡组增高并上移，少时保留留白；同样六卡不能锁死相同纵坐标。图标与卡头同色，正文从下一行开始，共用左对齐线。

主标题保留主体、动作与必要状态，优先一行居中；可有限缩字，但先删冗词，不能为单行无限缩小、压扁或裁字。卡头用短而具体的方面名，正文无衬线、层级稳定。关键数字局部加粗，产品/模型/术语用浅底行内词条；词条优先完整移到下一行；单个英文、数字或词条若超过整行宽度，先用更宽布局或在不改变含义的前提下整理写法，不能撑破卡片或硬切专名。不要全篇加粗或堆全彩品牌 Logo。

先用标题回答“发生了什么”，卡片各解释一个方面，口播补充关系和影响，不逐字重复满屏正文。资料出现时应帮助听懂正在说的主张；资料撤回后让观众有机会看清总结。新案例中的单卡、两卡和多卡都可用，不把复杂报告所有类别硬塞进一张六卡页。长专题按报道问题分段，底部用各段的短名定位；不要把同一报告的多个角度说成多起独立新闻。

可拟合的1080p范围：六卡左右外边距约100px、列宽约550–560px；两/四卡总宽约1500px；单卡宽约980px；卡间距约24–30px，圆角约28–34px，内边距约26–32px。标题常见62–82px、卡头40–46px、正文31–36px、行高1.35–1.5。它们是试排起点，实际以 profile、可读性和实测边界为准，不是识别出的源文件值。

## 概览、导航与告别

开场段的上方栏目名和下方分段名统一显示“总览”（`visual.overview_nav_label`），不再显示 Intro；内部布局仍使用 `overview`。

概览固定日期与星期；分类卡分两列，正文在共同滚动层内同步向上，窗口上下有渐隐。保留首屏停留→移动→停留→必要时再移动→末屏停留；按当天内容高度决定距离和是否需要第二次移动，不能照抄参考某一期259/66px。日期、字幕和上下导航不随列表移动。

开场以“大家好”、当天日期、“AI新闻”、概览提示、进入详细报道组成简短仪式，可复用已验证且文字一致的固定音频缓存；日期必须重新核对。含旧早报/晚报栏目名或早晚问候的开场按当前中性口径重新合成，沿用本期配置与有效缓存。不能因参考开头录音不全而人为留两秒无声。

上方显示当前栏目，蓝色整段高亮加白字；下方用每条新闻的短名和底缘增长线提示进度，不全做成上方一样的实色高亮。按最终时间计算段宽与位置：分母是包括概览、正文和告别的整片时长。上栏合并同类新闻，下栏逐条保留；空栏目不显示，短栏标签不强塞完整标题。

底部导览固定可见，包括资料覆盖期间。使用 profile 中64px底栏、最高28px文字、当前项白底蓝字加粗、清楚分隔线和6px进度线。短名优先2–6个字，必要时在完整词组间分两行；时长比例不能为放文字而造假。先改短名，不把英文专名拆成难认字母堆，也不把所有标签缩成蚂蚁字。渲染器完整试排，放不下会记入 `video-qa.json.navigation_notes`，不截取前两行冒充完整标签；新闻项有此记录须缩短标签并重验。极短的总览/结束可保留真实分段而省略挤不下的文字，人工记录。六段案例中约24条的拥挤导航是需修正的缺陷，不是目标。

告别沿用最后新闻基础页，只更新简短再见字幕和最右独立结束时间段，不另造长片尾。没有传闻也可正常结束。录屏的播放键、外部进度条、黑边、桌面闪现、蓝白浮层和结尾重播全部排除。

## 资料层与轻动效

资料窗口按下列规则实测；本仓库不携带私人历史样片和第三方网页截图。

主动采集真实原网页/原帖、官方发布图与可核验演示，维持认可版有充分原文资料的观感。认可版12条中9条有资料、总计11份，其中新增8处网页局部；这是密度参照，不是按图数验收。每条先判断最有用的原始视觉证据，抓取失败、没有适合图片或卡片已足够的具体取舍写入内部媒体记录，不能因为省事整片只放文字卡。每条零到多份资料，按报道任务决定出现位置；卡片建立主题可短可长，资料可跨多个字幕保持，也可退回基础页后再次展示。区分证明出处、解释和功能演示；相关 UI 演示不能代替数值榜单，不能说每句都严格声画对应。

资料保留原比例居中 contain。默认资料窗口上限为1600×720px，固定避开来源行、字幕与导航；横图以宽限制，长图以高限制，超宽图只占中间带状区域。资料出现时基础页继续存在，主体加轻暗罩（约0.14是拟合起点）；导航保持清楚，字幕在资料上方。关键来源、金额、限制和可读数字避开字幕，不复制参考的下沿遮挡。

取景可为原文局部、媒体标题/署名、分段长线程、价格表或完整操作窗口。保留必要的说话人、账号、日期、引用关系、表头和基线；可加明确的编辑性蓝色来源栏，但官网正文必须保留真实像素，不能重新排版冒充原网页；内容太小就局部取景或做明确标注的整理图，不无限缩小整篇原文。中文译文也属公开事实，必须核对。

来源页“看起来真实”不等于支持旁白：显示一条时间更正帖只能证明这次更正，不能顺带证明“大量用户已恢复”。同屏原文与所讲主张不对应时换取景或明确它只承担出处说明；带限定的原句不能被字幕、裁切或覆盖层挡住。长表只展示相关行列并保留表头、单位和比较条件；横向截图缩到普通观看窗口后无法阅读，就重新取景，不能靠观众暂停放大弥补。

静态与动态按实际素材选择：操作、生成过程、光标/窗口变化、宣传片多镜头需要视频时段；稳定截图就按图片使用。软件界面本身不能证明素材在动。保留新闻有关的运动，不把视频随意截一帧后宣称复刻了原演示。默认资料视频原声不与主配音叠加，若需保留原声应明确编排并检查混音。

卡片通常随整页共同出现。主要运动来自短切页淡化、资料出入、概览和进度；可从页面/资料约0.2–0.3秒淡化开始。资料间可以先退再入，不假定始终重叠；小幅缩放只在有目的且看过实际结果时使用。公开配置默认关闭点击音效。自行配置有使用权的音效时，上一句结束后先完整响完点击，短暂停顿后再进入下一页与口播；点击期间保留上一页。保留完整尾部并按旁白校准响度。开场、告别、字幕换屏与资料切换不额外连响。不要无依据地加弹跳、旋转、强推拉、炫光或逐卡飞入。

## 字幕与男声实现

字幕以白色无衬线字配半透明中灰小圆角底框，单行居中、宽度跟文字变化，位置在下方目录之上。优先清晰完整的意群，保留规范品牌、人名、版本、数字单位和日期；超宽就在完整意群之间提前分屏，不能拆成“Paul / Christiano”“2026 / 年…”或把顿号丢到下一屏。单行外观不高于可读性，不机械限每屏3秒，也不把上一条字幕无条件延长到下一条。

规范口播先按完整新闻写顺，再用完整自然句的 `speech_units` 合成，避免每个短字幕独立起调。`text` 处理发音，`display` 保留规范写法；一个单元需要分屏时，使用实测句内边界与对应显示文本，具体接口见 episode-format。自动估计或ASR不是已验证的精确对齐；修改发音后重新检查相应单元的长度与字幕。

默认使用 Qwen3-TTS Dylan 男声及profile的语气参数；不后期倍速、升降调。安装者可按明确偏好配置声音，仍需逐期核对专名、缩写、日期、金额与漏句。实际发音稿可展开缩写，规范字幕不跟随ASR同音错字改写。检查模型首尾静音与人工停顿的总时序。

参考录屏的音量受播放增益影响，不能直接复制其电平或将约190Hz作为男声目标。没有直接听辨就不能认定气声、呼吸、混响、音源、声音克隆或BGM；也不能宣传男声87已匹配原UP听感。公开配置默认无BGM，旧清晨配乐只作为显式选项；实际音频目标与检查按 profile/operations。

## 验收顺序

先检查所有公开层的事实边界和编排，再看声音/字幕、卡片、资料、导航和细节。实际抽帧应覆盖最长标题、最长专名、最密卡、最少卡、资料每次进出、概览和告别；缩小到普通观看窗口再看。检查模板残留如 `icon:timeline`、未替换占位文、无关旧版本号、卡片裁字和来源遮挡。结构与解码通过不能证明审美、自然发音或事实正确；未做的检查如实记录。

原始视频参考和私有分析产物未随仓库发布；新的新闻证据必须从真实原始来源取得。
