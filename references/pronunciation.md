# A 男声的发音稿与逐期检查

保持 profile 中所选 Qwen3-TTS Dylan 音色、语气指令与参数。按完整自然句生成，保留自然速度、重音与句尾；只修整过长的数字静音，做低频清理和响度控制，不套回旧男声的低通、压缩、去点击链，不做后期倍速或移调。

`speech_units.text` 是实际发音稿，`display`/speech 是规范字幕和公开文字。改读法不能丢掉资格、日期、额度和状态。以下是本项目观察到的问题与已用过的处理，不代表模型今后自动免检：

|表达|实际发音稿的处理|字幕及复核|
|---|---|---|
|AI|中文口播默认展开“人工智能”，避免旧片读成“哎”|字幕仍写 AI；确需念缩写时核对真实字母读音|
|Alt|可写“A、L、T 键”，再连接“加空格”|字幕保留 Alt + Space 等规范写法，检查三个字母都在|
|Preview|在中文版本介绍中可说“预览版”|保留规范产品名与版本号，不改变发布状态|
|ChatGPT / GPT / API|保留英语读法或分明的字母名；必要时调整整句，重新生成|v03 的 Chat G P T 仍出现过 ASR 的 G B T 近音转写；插空格本身不是修复证据，不能宣称全部读对|
|版本、数字与金额|发音稿写清楚“二点八”“九月十四日”“一百美元”“十五个小时”等|画面使用规范数字；核对小数点、年月日、单位、滚动周期和套餐范围|
|标点与路径|不让英文标点名、接口路径或长URL混进正常口播；改为自然解释|检查意外 DOT/COLON 插读，不能为规避朗读而改错模型/调用名|
|产品英文名|结合中文句子保留清楚的英文名称，避免连续堆长串专名|DeepSeek、Kimi Code、Gemini、Cohere、Astra、Codex 等识别音译只能作为疑点，不能直接改成 ASR 错字|

生产时自动生成 `pronunciation-inventory.json`：逐句并列规范文字、实际发音和英文/数字表达，并标出可能有问题的原样 AI。合成前按清单整理稿件；合成后核对最终 MP4 转写，必要时对疑点完整句单独核听或转写。发现真实错读、漏字或截尾就修改该句并重配，再重算相关字幕/资料时刻。最终检查与该次视频哈希绑定。

安装者选定音色后，每期新文字仍须检查。不能用 ASR 转写相似、无削波或用户认可旧样音来代替整片主观听审。没有直接听辨能力时使用 `asr-and-signal` 并保留实际局限；已知的发音缺陷需要修正，纯识别不确定性应单独记录。
